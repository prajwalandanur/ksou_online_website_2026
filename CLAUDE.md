## 1. Project Overview

**KSOU Online** — the online-programmes website for Karnataka State Open University, a government university in Mysuru, Karnataka. This is a production-grade project for a government institution, built to the same engineering standard as a commercial enterprise product: clean architecture, scalability, performance, accessibility, SEO, and security are not optional.

Design goal: feel like a premium modern SaaS/education platform (Linear, Stripe, Vercel, Notion, Online Manipal) — **not** a traditional government website. Premium, elegant, minimal, spacious, trustworthy, conversion-focused. Design inspiration comes from the latest Online Manipal website, without copying it — KSOU Online needs its own identity.

Carousels/scroll mechanisms have kept growing hand-rolled instead of converging on Swiper — there are now **three distinct home-grown mechanisms**: `useAutoScrollCarousel` (interval-based autoplay, used by the accreditation strip and the course-grid mobile carousel), `useMarquee` (real `scrollLeft` + `requestAnimationFrame`, infinite-loop via duplicated content, used by the Why Choose KSOU feature strip), and a third pattern with no shared hook at all — manual scroll-snap + explicit Prev/Next buttons, no autoplay (`BlogCarousel.jsx`). This is the inconsistency the original note warned about; worth a deliberate look (converge on Swiper, or extract the third pattern into a shared hook) before adding a fourth.

Path alias: `@` → `src/` (configured in `vite.config.js` and `tsconfig.json` — a plain-JS project intentionally keeps a `tsconfig.json` only so editor tooling and Vite's dependency scanner resolve paths; there is no actual TypeScript in this project).

## 3. Design System

Defined in `src/index.css` under `@theme`. Tailwind v4's CSS-first config means these `--color-*`/`--font-*`/`--shadow-*` tokens automatically become utility classes (`bg-background`, `text-primary`, `font-brand`, `shadow-card-rest`, etc.) — don't hardcode hex values in components, use the tokens.

**Colors**
| Token | Value | Utility |
|---|---|---|
| Background | `#FFFFFF` | `bg-background` |
| Primary text | `#111111` | `text-foreground` |
| Primary accent | `#4169E1` (royal blue) | `bg-primary` / `text-primary` |
| Accent hover | `#3457C9` | `bg-primary-hover` |
| Muted background | `#F6F7FB` | `bg-muted` |
| Muted text | `#6B7280` | `text-muted-foreground` |
| Border | `#E8E9ED` | `border-border` |

White-on-`#4169E1` contrast was checked: ~4.85:1, passes WCAG AA at any weight/size.

Tailwind's built-in `amber-400` has since been adopted as a small decorative accent (dot separators, the traveling dot on the How It Works timeline) — used consistently across `BlogCard`, `FeatureCard`, and both `JourneyDesktop`/`JourneyMobile`. It's a deliberate, consistently-applied choice but isn't a `--color-*` token yet — promote it to one (`--color-accent` or similar) if it keeps spreading, rather than letting bare `amber-400` proliferate.

**Typography — current system (this has changed twice; this is the standing one, confirmed explicitly by the user):**
- **Headings / brand:** DM Serif Display, `font-brand` utility. **Only weight 400 exists** — this font has no bold instance on Google Fonts/Fontsource. Never apply `font-bold`/`font-extrabold` to anything using `font-brand`; get visual weight from size and letter-spacing instead.
- **Body / nav / buttons / everything else:** DM Sans, weights 400–700 available, `font-sans` utility (this is also the `<body>` default, so plain text needs no explicit class).
- Both are **self-hosted** via `@fontsource/dm-serif-display` and `@fontsource/dm-sans` — imported in `src/index.css`, actual font files live in `node_modules`, nothing is loaded from Google Fonts/any CDN at runtime.
- **Standing project convention: always self-host fonts.** Never add a `<link>` to an external font CDN. If a requested font isn't on `@fontsource`, download the actual files (e.g. via the foundry's API) and vendor them under `src/assets/fonts/` with local `@font-face` rules. This has been applied consistently (Google Fonts → Fontsource; a Fontshare-exclusive request was downloaded and vendored rather than linked live) — see the project's Claude memory for the full history if it matters.
- Prior iterations, fully removed (packages uninstalled, files deleted) — **do not resurrect these**: Plus Jakarta Sans + Inter (initial build), General Sans + Satoshi (a later Hero-only experiment, self-hosted from Fontshare).

**Kannada typography:** `html[lang='kn']` in `src/index.css` swaps `--font-sans`/`--font-brand` to the Noto Kannada faces **and, since 2026-08-21, resets every widened `tracking-*` utility to `letter-spacing: normal`**. That second rule is not cosmetic. Kannada is an abugida — a written unit is a base consonant plus its vowel sign and conjuncts — so the site's `uppercase tracking-[0.18em]` eyebrow pattern inserts space *inside* a cluster: at 14px that is 2.52px, and `ಶೈಕ್ಷಣಿಕ` renders as `ಶೈ ಕ್ಷ ಣಿ ಕ`, i.e. it stops reading as a word. 19 elements on `/kn/about` alone were affected, and every other `/kn` page shares the pattern. `text-transform: uppercase` is separately inert there, since Kannada has no letter case. The selector deliberately leaves `tracking-tight` (-0.025em) alone: it is too small to break clusters, and neutralising it would reflow headings on Kannada pages that are already reviewed. English is untouched — verified at 2.52px on `/about` after the change.

**Other tokens**
- `--shadow-card-rest` / `--shadow-card-scrolled`: the layered elevation scale used by the floating Navbar card (and reused conceptually elsewhere) — resting vs. scrolled/lifted state.
- Large border radii throughout (20–28px range) for the "floating card" aesthetic — e.g. `rounded-[26px]` on the Navbar card, `rounded-[28px]` on course/hero cards.
- Generous whitespace, soft multi-layer shadows, thin `border-border` hairlines, soft hover lift (`hover:-translate-y-*` + shadow bloom) — this vocabulary repeats across every section built so far and should continue.
- Mobile-first responsive; breakpoints follow Tailwind defaults (`sm`, `lg` are the two used most).

## 5. Coding Standards (established and followed so far)

- Functional components + hooks only, no class components.
- Data/copy lives in `src/constants/*.js`, never hardcoded inline in JSX — e.g. nav links, phone numbers, course list, accreditation logos are all constants files imported by components.
- Reusable primitives over duplication: `Button.jsx` has `primary` / `secondary` / `ghost` variants (plus `onPrimary` / `outlineOnPrimary` for CTAs that sit on a solid primary-blue background, e.g. the MBA page's final CTA panel — added because overriding another variant's bg/border/text-color classes via a later `className` is unreliable, since Tailwind's generated CSS order for same-property utilities doesn't follow JSX class-string order, so the base variant's own class can still win the cascade) and handles `<Link>` vs `<a>` vs `<button>` automatically based on `to`/`href` props; `CourseCard` is one component reused across both the grid and the carousel; `useAutoScrollCarousel` is one hook reused by both the Hero's accreditation strip and the Courses carousel (parameterized by interval).
- Local state by default; no global state library introduced (none has been needed yet).
- Accessibility baked in throughout: semantic HTML (`<header>`, `<nav>`, `<section aria-labelledby>`, one `<h1>` per page), keyboard focus rings (`:focus-visible`), ARIA on the mobile menu (`role="dialog"`, `aria-modal`), descriptive `aria-label`s, `cursor-pointer` on all clickable elements, and every Framer Motion animation respects `prefers-reduced-motion` via `<MotionConfig reducedMotion="user">` in `App.jsx` (the two carousels additionally check `matchMedia('(prefers-reduced-motion: reduce)')` directly since their autoplay is a `setInterval`, not a Motion animation).
- Every section built has gone through: `npm run lint` (ESLint flat config, must be clean) → `npm run build` (must succeed with no errors) → dev server smoke-test (curl every touched file for a 200) before being considered done. Chrome browser tools failed to connect across several early sessions but connected successfully as of 2026-08-11 (fix: fully quit and relaunch Chrome, confirm the signed-in profile matches the Claude Code session) — desktop viewport now visually verifiable via the extension. **Mobile-viewport QA no longer goes through the extension at all** — its `resize_window` tool resizes the real OS browser window via `chrome.windows.update()`, which silently no-ops when the window is maximized (confirmed live: `outerWidth` stayed pinned to `screenAvailWidth` before and after the call, and the tool's schema has no `state` param to un-maximize first), so it could never reliably reach a mobile layout. Fixed by adding `playwright` as a devDependency instead: `npm run qa:mobile` (`scripts/mobile-screenshot.mjs`) launches headless Chromium with real device emulation (`iPhone 13` profile) — a genuine viewport override, not OS window resizing — and screenshots the homepage + all 6 programme routes to `qa-screenshots/mobile/` (gitignored-worthy output dir, not committed content). Verified against real screenshots showing correct mobile layout (compact navbar, single-column stacked cards, mobile carousel dots) on both Home and the MBA programme page.
- **Scroll position resets to top on every route change** — `components/common/ScrollToTop.jsx`, rendered once inside `<BrowserRouter>` in `AppRoutes.jsx`. React Router doesn't do this automatically (no full page load between routes), so without it, clicking a card while scrolled down on the previous page landed mid-scroll on the new one — this was reported as a real bug and fixed by calling `window.scrollTo(0, 0)` in a `useEffect` keyed on `location.pathname` only (not the full `location` object), so in-page anchor jumps like the blog Table of Contents (hash-only navigation, same pathname) aren't affected.
- No external runtime dependencies beyond what's necessary: fonts are self-hosted (see §3), no analytics/tracking added, no third-party scripts.

1. **Navbar / header system** (`src/components/layout/Navbar/`) — **three stacked bands, only the middle one sticky**: utility row (language toggle EN/ಕನ್ನಡ + the `CONTACT_NUMBERS` helplines — **2 of them, not 3**, whatever older notes in this file say, visible at **every** breakpoint), main row (KSOU crest + bilingual wordmark, nav links with pill hover/active state, and two CTAs — Apply Now / Login, LMS Login), and the announcement ticker. Full-screen animated mobile drawer with hamburger toggle below `xl`.
   - **The logo is the crest plus a supplied bilingual wordmark image** (`src/assets/ksou-crest.jpeg` + `src/assets/ksou-title.webp`), as of 2026-08-13. It replaced the old two-line text block ("KSOU Online" in `font-brand` over a small grey "Karnataka State Open University"), on explicit instruction. Two consequences worth knowing: the "KSOU Online" brand name no longer appears as text anywhere in the header, and the university name is now baked into an image, so it is **not** translatable by the i18n layer — which is fine only because the artwork is already bilingual (Kannada above, English below). Both `<img>`s carry `alt=""` because the wrapping `<Link>` supplies the accessible name via `aria-label`; giving either one real alt text would double-announce or override that label. **Width is the constraint, not height:** at `lg:h-8` the wordmark renders ~168px, marginally narrower than the text line it replaced, which preserves the ~24px of nav-row slack at 1280px. Measured after the swap: header 187px and zero overflow at 1280, 54px at 390.
   - **There is now ONE header for every breakpoint** (2026-08-13). It used to be two — a `DesktopHeader` whose whole three-band card was the sticky element, and a `MobileHeader` that pinned only the nav row — swapped at 1024px by `useMediaQuery`. The brief asked for the mobile behaviour everywhere *and* asked to stop mounting/unmounting header components, so the two were merged. `useMediaQuery` is no longer used anywhere in the codebase (the hook file remains).
   - **`Navbar` returns a fragment, and that is load-bearing.** The utility bar, the `<header>` nav row and the ticker are direct children of the unstyled `#root`. Only the nav row is `sticky top-0`; the other two are ordinary flow content that scrolls away going down and returns at the top. `position: sticky` is bounded by its parent, so wrapping these three in any container unsticks the nav the moment that container scrolls past — that was an early failed attempt.
   - **The desktop floating rounded card is gone.** This is the one real visual change: the nav row is now a full-width opaque band flush to the viewport top, at every width. It had to be — the brief required "no gap, no thin line, no white strip, no visible opening" above the pinned navbar, and the old card's `pt-4`, side gutters and rounded top corners produced exactly that opening once stuck. Keeping the card at rest and squaring it off on scroll would have meant a scroll-driven size change, i.e. the flicker bug below. Page content still uses `max-w-7xl`; the nav row's *inner* container is `max-w-[90rem]`.
   - **Nothing animates on scroll and no element ever changes size.** That is the whole flicker fix — an earlier version collapsed bands on a `scrollY > 24` boolean, and because a sticky element reserves its own flow space, each collapse shortened the document and shoved the page, which could re-cross the threshold and oscillate. `useScrolled` drives only a shadow, a paint-only property. Re-verified after the merge: 51 scroll positions across the threshold at 1440 saw exactly one nav height and one document height; at 390 and 1440 the nav pins at `y=0`, `elementFromPoint(centre, 1)` lands inside `<header>`, and both the utility bar and ticker have scrolled fully out of view. **Do not reintroduce a scroll-driven height, padding or collapse.**
   - **Two constraints the sticky row depends on:** it must be fully opaque (`bg-background` — verified `rgb(255,255,255)`), or the ticker shows through as it scrolls underneath; and no ancestor may have a non-visible `overflow`, which kills sticky. The old card's `overflow-hidden` went with the card.
   - **Two CTAs sit in the row at every width: "Apply Now / Login" (gold) and "LMS Login" (blue).** Gold is a `Button` variant with **navy** text — white on gold is ~1.9:1, navy is 6.25:1. This is the only place `--color-gold` carries text; everywhere else it is a decorative hairline or dot. `--color-gold-hover` was added for it.
   - **Fitting nine items on one row was measured, not guessed.** Before tuning, the row overran by 73px at 1280 and 187px at 320. The room came from padding and the logo, **not** from the 14.5px nav type: link padding `px-3.5 → px-2` (restored at 2xl) gave back 84px, row gutters and gaps ~24px, and the wordmark drops to `xl:h-7` for 21px. The CTA labels shorten to "Apply Now" with the arrows hidden below `sm` (the arrows alone were 40px). **Anything added to this row must be re-measured at 320 and 1280 — those are the two binding cases.**
   - **The bilingual wordmark now shows at every width, including phones** (2026-08-14, `Logo.jsx`). It used to be `hidden … sm:block`, with a live-text "KSOU Online" lockup standing in below `sm`; that lockup is **deleted**, on request that the university title appear beside the crest on mobile in both the header and the footer. One `Logo` serves the header, the footer and the drawer, so the single change covered all three.
     - The measurement that made it possible: at 390px the row had **zero** slack (368px of content in a 366px row) and was already overflowing by **59px at 320 and 19px at 360** — a real pre-existing bug, despite what this file used to claim. The room came from `Button`'s new `size="nav"` (see below), which finally applies the compact phone padding the navbar had been asking for and not getting, plus a smaller hamburger and logo gap below `sm`. **Both CTAs stayed** — an interim version dropped LMS Login below `xl` to make room and that was rejected; shrink the buttons, don't remove one.
     - Resulting wordmark widths, all at **0px overflow** (320/360/390/414/768/1024/1280/1440, English and Kannada): full 147px from 390 up, 126px at 360, 86px at 320. Only below 390 is the artwork scaled down by the safety net rather than the row being broken. If that is ever not good enough, the next lever is **shorter CTA labels below `sm`** ("Apply"/"LMS" via the two-span pattern Apply Now already uses), worth ~50px — **not** smaller type: 9px is the floor for these labels.
     - **`min-w-0` on the `<Link>` (and no `shrink-0`) plus `max-w-full min-w-0 shrink object-contain` on the `<img>` is the safety net, not decoration.** Where even `h-7` is wider than the leftover space the box narrows and `object-contain` scales the artwork down inside it, letterboxed rather than stretched — that is what holds 320px (renders 109px) and the Kannada nav row at 1280px (renders 126px, since Kannada links are wider). Restoring `shrink-0` reintroduces the overflow.
     - **`Button` now takes a `size` prop** (`SIZE_CLASSES` in `buttonClasses.js`; `default` = the old `px-5 py-2.5 text-sm`, `nav` = the header scale). **When a step changes, change padding and type together** — the scale holds side padding ≈ 1.0x the font size and vertical padding ≈ 0.65x at every step, and a pass that cut padding to `px-1.5` while leaving 10.5px labels was rejected on sight for crowding the pill edges. The two phone steps (`px-2 py-1.5 text-[9px]`, then `px-2.5 text-[10.5px]` from 400px) keep those ratios. This whole prop exists because padding/type could not be shrunk from a `className` — and the failure was **partial**, which is why it went unnoticed for so long: `px-5` and `px-2` are the same utility at different scale steps with equal specificity, so Tailwind's emission order picks the larger one, but a `sm:px-3` *does* win because variants are emitted after all base utilities. The navbar's `sm:`/`xl:`/`2xl:` sizes were live while its bare `px-2 py-1.5 text-[11px]` was dead, so phones — the only width that needed the compact size — rendered full desktop padding. Worth ~46px. **Never override button padding or font size through `className`; add a named size.** Every other caller is unaffected: `default` emits the identical class string, so the cascade there behaves exactly as before (including any other caller whose unprefixed override is still silently losing — not audited).
     - Consequence to keep in mind: **the words "KSOU Online" no longer appear as live text anywhere in the header or footer** at any width — the brand name is only in the crest link's `aria-label` and in page copy. The university name is likewise baked into an image and so is **not** translatable by the i18n layer, which is only acceptable because the artwork is already bilingual.
   - **The utility bar shows on mobile too** and fits "Language | number | number" on **one 27px row from 375px up**. Getting there took: 10.5px numbers, one leading phone icon for the whole group instead of three, `•` separators, and `LANGUAGES[].short` ("EN" for English; "ಕನ್ನಡ" is its own abbreviation) with the globe icon hidden below 420px. At 320–360px it wraps to two slim rows (42px) — unavoidable, the content is simply wider than the viewport at any readable size.
   - **Phone numbers are the real admissions lines** (`CONTACT_NUMBERS` in `constants/navigation.js`) and are styled to stand out from the bar's muted grey: navy, semibold, 13.5px desktop / 12.5px mobile, with the icon in KSOU blue. `label` and `href` must stay in sync — that pairing exists so the displayed digits can't drift from the dialled ones.
   - **`scroll-mt-*` on blog headings is coupled to the header height** (`ArticleBody.jsx`, `BlogArticlePage.jsx`'s FAQ section — currently `scroll-mt-60 md:scroll-mt-52`). **Both values now have far more slack than they need**, because since the header merge only the nav row is ever pinned: 53px at 390 and 73px at 1440, not the whole 110/186px header. Worth trimming to roughly `scroll-mt-20 md:scroll-mt-24` next time this is touched; harmless as-is, just a large gap above a jumped-to heading.

   - **`EnquiryForm` has two containers, and only one implementation** (2026-08-19): `EnquiryModal` mounts it in the timed popup, `ContactEnquiryCard` mounts it permanently on `/contact` (§6 item 13). A `sm:`/`lg:` variant would have widened the popup's fields on exactly the large screens where its panel is still 448px. Verified live at both call sites.
   - **A submission on `/contact` does not cancel the popup sequence.** `markSubmitted` lives in `useEnquiryPopup`'s local state, which the contact card has no handle on, and the brief for that page was explicit about not changing popup trigger behaviour. So a visitor can submit the page form and still be shown the popup 25s later. Fixing it means giving the hook a module-level subscription, not a second timer.
   - **⚠ No lead destination is wired.** `services/enquiry.js` POSTs to `VITE_ENQUIRY_ENDPOINT`; with that unset — the current state — a submission is `console.warn`ed and reported as successful so the confirmation state still works, **and the lead goes nowhere**. Set the variable to a form-capture service, a serverless route or a CRM webhook before launch, or the popup collects prospective students' details and drops them. A non-2xx response or a network failure surfaces a retryable error rather than a false "Thank You".
   - **The schedule is behavioural, not a fixed interval** (rewritten 2026-08-19; it was 25s → +60s → +30s on pure timers). Three appearances, each on a *different kind* of trigger, then never again — the escalation is the point: engagement, follow-up, then one last attempt only as someone leaves.
     1. **50% scroll depth OR 60s from entry, whichever comes first** — a race; whichever fires disarms the other.
     2. **60s after dismissing the first.** Measured **from dismissal, not from appearance** — measuring from appearance would fire popup 2 the instant someone who actually *read* popup 1 closed it. `dismiss` clears `nextPopupAt`, and the next arming recomputes from "now"; that deletion is what implements "from dismissal".
     3. **Exit intent** — `mouseout` with `clientY <= 0` and no `relatedTarget`, i.e. the pointer leaving past the top edge. **No timer at all on this one**, so a visitor who never leaves never sees a third popup.
     - `POPUP_TRIGGERS` in `constants/enquiry.js` *is* the schedule — an array of descriptors indexed by `shownCount`, with `MAX_POPUP_APPEARANCES` derived from its length. The hook branches on which fields a descriptor carries (`delayMs` / `scrollDepth` / `exitIntent`) rather than on a name, so changing the sequence is a data edit.
     - **Scroll depth is `(scrollY + innerHeight) / scrollHeight`** — proportion of the document *seen*, the way analytics reports it, not proportion of the scrollable distance (which would call a two-screen page half-read after one flick). Only ever evaluated inside a scroll handler, so a page too short to scroll emits nothing and its timer governs — that is also what stops a short page from firing during first paint.
     - **`EXIT_INTENT_ARM_DELAY_MS` (5s) is not padding.** Dismissing the second popup means moving the cursor *up* to the ✕ in its corner; without the delay, a visitor continuing in that direction gets popup 3 within a second of closing popup 2.
     - **⚠ Exit intent is pointer-only, so the third appearance effectively never fires on phones.** There is no touch equivalent; a tab-hidden or history-back fallback would be a deliberate addition, not a bug fix.
     - Verified live, all in one run: 7.5s on scroll / 63.2s on the timer when nobody scrolls / +59.9s from dismissal / exit intent ignored during the arm delay then firing on it / no fourth after scrolling and exit intent again / reload mid-wait resumes at 63.0s total rather than restarting.
   - **A captured lead suppresses the popup for 7 days, and `EnquiryForm` is what sets it** (`suppressEnquiryPopup()` in `services/enquiryStorage.js`). Consequences worth knowing: it is **localStorage**, not session — a session flag would forget by the next visit and ask someone who already applied all over again; and because it lives in the *form*, a submission on `/contact` silences the popup exactly like the popup's own copy does, **including on the same screen without a reload** (the hook reads it through `useSyncExternalStore`, so a mounted controller hears the write immediately). That closes the gap this file used to record as unfixable without a subscription. A future third surface inherits it for free. `useEnquiryPopup` no longer exposes `markSubmitted`, and `EnquiryModal` no longer takes `onSubmitted`.
   - **The popup never appears on the six programme detail pages** — `SUPPRESSED_PATH_PREFIXES = ['/programmes/']`, matched against the language-stripped pathname so `/kn/programmes/mba` is covered. **The trailing slash is load-bearing**: `/programmes`, the listing, still shows it. Suppression gates *arming*, not just opening, and the path is a dependency of the arming effect — so a countdown that elapses while the visitor sits on a programme page is not lost, it is released ~5s after they leave (verified at 6.1s), while landing directly on one arms nothing until they reach another route.

   - **A hard reload resumes the schedule instead of granting a fresh 60s**, because the due-time is mirrored into `sessionStorage` (`ksou.enquiry.*`).
